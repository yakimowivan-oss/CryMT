**CryMT v13: launcher, global illumination, updates**

## Русский

Первая сборка с лаунчером. Дальше обновления приходят прямо в нём.

**Установка**
1. Распакуйте архив в папку игры (где Bin64).
2. Запустите `CryMT\CryMTLauncher.exe`.

Нужен c1-launcher v8 в роли `Bin64\Crysis.exe`.

**Новое с v12**
- **Лаунчер.** Готовые режимы (Ваниль / Только MT / MT+DX12 / MT+DLAA / Полный), все настройки с подсказками, список клавиш, обновления с проверкой подписи и откатом.
- **Глобальное освещение** (режим «Полный»):
  - воксели вокруг камеры, геометрия сцены в них;
  - экранная часть по методу visibility bitmask;
  - GTAO вместо SSAO;
  - контактные тени;
  - освещение и затенение дыма, пыли и тумана.
- **DLAA.**
  - Нет дрожания на стоящей камере: пост-обработка игры получает уже сглаженную сцену.
  - Бинокль: второй зум больше не замораживает картинку.
- **Быстрее на процессоре.**
  - Свой z-проход: пачки объектов уходят с потока рендера, на harbor 1.62 → 0.62 мс.
  - Объединение отрисовок общего прохода: −1 мс.
- **Без фризов.**
  - Новые состояния конвейера создаются в фоне.
  - Процедурная растительность генерируется по бюджету на кадр.
  - Сохранение пишется в фоне: фриз 330 → 165 мс.
- **Захват кадра в RenderDoc** для разработки: `CRYMT_RENDERDOC=1`, клавиша PgUp.

## English

The first build with the launcher; from now on updates arrive through it.

**Install**
1. Unpack into the game folder (where Bin64 is).
2. Start `CryMT\CryMTLauncher.exe`.

c1-launcher v8 is required as `Bin64\Crysis.exe`.

**New since v12**
- **Launcher.** Ready-made modes, every setting with an explanation, a key list, and signed updates with rollback.
- **Global illumination** ("Full" mode):
  - voxels around the camera, with the scene's geometry in them;
  - a screen part using a visibility bitmask;
  - GTAO in place of SSAO;
  - contact shadows;
  - lit and shaded smoke, dust and fog.
- **DLAA.**
  - No more shimmer on a still camera: the game's post effects now get the anti-aliased scene.
  - Binoculars: the second zoom no longer freezes the image.
- **Less CPU time.**
  - Own z-prepass: object batches leave the render thread (harbor 1.62 → 0.62 ms).
  - The general pass merges draws: −1 ms.
- **Fewer hitches.**
  - New pipeline states are created in the background.
  - Procedural vegetation is generated within a per-frame budget.
  - Saves are written in the background (freeze 330 → 165 ms).
- **RenderDoc frame capture** for development: `CRYMT_RENDERDOC=1`, then PgUp.
